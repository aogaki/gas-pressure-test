# 08 241Am 実データによる較正と閉ループ

前提: TODO/06, 07。状態: 設計 (2026-09-07)。実効ゲイン G と幾何の確認を、tpcdaq-rs の 241Am のデータで行う。

## 実測の配置 (2026-09-07 に聞き取り)

- 線源は 241Am (主線 5.486 MeV 85 %、5.443 MeV 13 %)
- 線源軸は加速器ビーム軸に直交する = シミュレーションの α 線源軸 (+z)。基板図の −y_det
- 線源は検出領域 (パッド面の上流端) から約 50 mm 離れている
- 横方向は中心から約 3 mm ずれている。左右どちらかは不明
- 線源の高さ (ドリフト方向の位置) とコリメータの有無は未確認。高さはデータの到達時刻分布から推定できる
- 実データの α は検出器を突き抜ける (TODO/07 の README の記述と一致)

## 幾何のモデル化

- 線源から 50 mm のガス (CO2 100 mbar) を通ってからパッド面に入る。シミュレーションでは α をガス入射面 z = −250 mm から出し、パッド地図を d = 50 mm で作る (`make_pads.py <dat> geometry/pads_d50.csv 50 channel_map.csv`)。パッドは z = −200 から −93.5 mm に来る
- テストは d = 0 の geometry/pads.csv のまま。較正のランだけ `channel-response -p geometry/pads_d50.csv` を使う。どちらも git には入れない (`geometry/*.csv` を gitignore)
- 横ずれは `/gps/position ±3 0 -250 mm` の 2 通りを走らせ、電荷の多い U ストリップの番号がデータと合う側を採る
- 高さはまず y = 0 (ドリフト 100 mm) とし、データの到達時刻の中心と合わせて直す。ドリフト 100 mm は v = 0.579 cm/µs (1600 V) で 17.3 µs、1200 V なら 23 µs

## 期待されるエネルギー (NIST ASTAR、CO2 100 mbar、密度 1.818×10^−4 g/cm3)

| 位置 | 質量厚 [g/cm2] | 残留飛程 [g/cm2] | エネルギー [MeV] |
|---|---|---|---|
| 線源 | 0 | 5.068×10^−3 | 5.49 |
| パッド上流端 (50 mm 後) | 9.1×10^−4 | 4.16×10^−3 | 4.90 |
| パッド下流端 (更に 106.5 mm 後) | 2.85×10^−3 | 2.22×10^−3 | 3.07 |

- パッド面上で落とすエネルギーは約 1.83 MeV。W = 33.0 eV で一次電子は約 5.5×10^4 個/イベント
- 線源に薄い保護膜があればエネルギーは下がる。較正結果に ±5 % 程度の不定性として残る

## 較正の手順

1. Stage 1: `/tpc/gas CO2`, `/tpc/pressure 100`, `/tpc/hits true`, `/gps/particle alpha`, `/gps/energy 5.486 MeV`, `/gps/position 3 0 -250 mm` (と −3 mm)、方向 +z、1000 イベント
2. Stage 2: `-v <データの電圧> -f 0.1`。run 2026-09-02 は 1600 V、run 2026-09-01 は 1200 V (2026-09-07 にラン記録と照合)。analyzeUVW.C の定数 DRIFT_HV_V = 1200 は 09-02 のランに合っていないので、09-02 のデータは定数を 1600 に変えたコピーで解析し直す (既存の `_uvw.root`, `_tracks.root` は z スケールが 4/3 ずれている)
3. Stage 3: `-p geometry/pads_d50.csv -w <窓の開始>`。窓はデータの到達時刻の中心に合わせる
4. Stage 4: `-t 223 -r 120 -g G -p 450 -s 6`。G は 1000 から始める
5. 実データ (`macros/data/CoBo_2026-09-02T14-30-48.869_raw.root`) とシミュレーションの両方に `external/tpcdaq-macros/analyzeUVW.C` を掛け、`hCharge` (イベントの総電荷) と `uvw` の qview[3] を比べる。総電荷はゲインに比例するので、ピークの比から G を決める。データの電荷分布の幅 (GEM のゲイン揺らぎ、線源のエネルギー分布) はシミュレーションより広いはずで、幅は合わせない
6. 決めた G で `makeTracks.C` まで通し、length と方向の分布をデータと並べる。データは突き抜けるので length はパッド面の幅で決まる。方向余弦は線源の向きの確認になる
7. 結果 (G、横ずれの符号、高さ、分布の図) をこの文書に記録し、`aget-shaper` の既定の `-g` を更新する

## 受け入れ基準

- 較正後のシミュレーションの `hCharge` のピークがデータのピークの ±5 % 以内
- 電荷の多い U ストリップの番号がデータと一致する
- `tracks` の length のピークがデータの ±10 % 以内 (幾何の確認)

## 未確認・相談

- 線源の高さとコリメータ。分からなければデータから推定する
- (済) ドリフト電圧: run 2026-09-02 = 1600 V、run 2026-09-01 = 1200 V。analyzeUVW.C の定数 1200 V は 09-01 用
- 241Am 線源の保護膜の有無 (エネルギー損失)
